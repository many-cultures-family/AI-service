# 2. 사람, 현재 흐름, 기존 서비스

> 목표: 누가 어떤 순서로 일하거나 이용하고, 어디서 막히는지 찾는다.

## 2-1. 이해관계자 (최소 3종류)

> '관리자', '사용자' 같은 말은 한 번 더 쪼갭니다. 누가 등록하고, 누가 승인하고, 누가 결과만 보는지가 다르면 다른 사람입니다.
> 예: 셀러 대표 / CS 담당 / 출고 담당 / 구매 고객, 러너 / 코치 / 러닝 크루 운영자, 결혼이민자 / 가족 / 센터 상담원 / 통번역사

| 이해관계자 | 이 서비스에서 하는 일 | 볼 수 있는 것 / 없는 것 | 가장 큰 불편 | 태그 |
| --- | --- | --- | --- | --- |
| 결혼이민자 (신청 당사자) | 받은 공고문·신청서·계약서를 올리고, 가상 신청서로 리허설한 뒤 공식 경로에서 직접 작성·제출·서명. 결과 통지를 올려 승인·반려·보완을 확정 | 볼 수 있음: 내 신청 건 목록과 상태, 연습 기록, 자립 기록, 모국어·쉬운 한국어 설명 / 볼 수 없음: 다른 사용자의 신청 건, 상담원 내부 메모 | 한국어 문장은 번역해도 '이 칸에 무엇을 어떤 형식으로 쓰는지', 본인인증·첨부 오류 때 어떻게 하는지 몰라 매번 남에게 의존함 | `[추정]` 1-2 디지털 활용 능력, C05(역량 수준 90.0%) / `[가정]` 형식·인증 단계에서 막힘 |
| 가족 구성원 (한국인 배우자·자녀) | 지금은 대신 읽어 주거나 대신 신청해 주는 사람. 서비스에서는 사용자가 동의한 경우에만 신청 건 진행 상태를 함께 봄 | 볼 수 있음: 사용자가 공유한 신청 건의 상태 / 볼 수 없음: 공유하지 않은 신청 건, 연습 중 입력값 | 대신 해 주느라 시간이 들고, 대신 해 주면 당사자는 다음에도 혼자 못 함. 자녀가 부모 서류를 대신 처리하는 역할 역전 | `[가정]` 5단계 인터뷰 질문으로 확인 |
| 가족센터 상담원 | AI가 만든 가상 신청서를 원본 서류와 비교해 수정·승인·반려. 담당 가정들의 진행 상태와 반복적으로 막히는 항목 통계를 확인 | 볼 수 있음: 검수 대기 양식, 원본 서류(개인정보 제거본), 사용자가 공개에 동의한 신청 건 상태, 막힘 통계 / 볼 수 없음: 실전 화면의 실제 입력값, 인증 정보 | 같은 종류의 서류를 가정마다 반복해서 설명·통역함. 운영 시간과 인력에 한계 | `[사실]` 센터의 교육·상담·통번역 업무(C01) / `[추정]` 반복 상담 부담 |
| 통번역사 (센터 통번역 지원 인력) | 상담원 검수 때 모국어 설명이 원문 뜻과 맞는지 함께 확인(검수 보조) | 볼 수 있음: 검수 대기 양식의 원문과 모국어 설명 / 볼 수 없음: 사용자 개인정보 | 문서 한 장마다 통역·번역 요청이 몰려 대기가 생김 | `[사실]` 통번역 지원사업(다문화가족지원법 제12조 제4항 제6호) / `[추정]` 대기 발생 |
| 서류를 내보내는 기관 담당자 (학교·주민센터·출입국 등) | 서비스를 직접 쓰지 않음. 공고문·신청서를 만들고, 접수·보완 요청·승인·반려 통지를 보냄 | 볼 수 있음: 공식 경로로 제출된 실제 신청서 / 볼 수 없음: 서비스 안의 연습 기록 | 형식 오류·서류 누락 신청이 들어오면 보완 요청을 다시 보내야 함 | `[가정]` 보완 요청 빈도는 미확인 |

## 2-2. 현재 흐름 (As-Is)

> 우리 서비스가 없다고 치고, 지금 사람들이 어떤 순서로 처리하는지 적습니다. 엑셀·메신저·종이·기존 앱·수업 자료 등 지금 쓰는 도구를 함께 적습니다.
> 화이트보드나 종이에 그린 뒤 사진을 `docs/domain/images/`에 올리고 `![현재 흐름](images/as-is.jpg)`처럼 붙여도 됩니다.

| 순서 | 누가 | 무엇을 하나 | 무엇을 쓰나 (도구·문서) | 여기서 생기는 문제 |
| --- | --- | --- | --- | --- |
| 1 | 기관 → 결혼이민자 | 공고문·신청서·계약서를 받음 (예: 자녀 방과후학교 신청 공고) | 종이 가정통신문, 학교 앱 알림, 문자, 정부24·하이코리아 공지 | 한국어 행정 용어(세대주, 증빙서류 등)와 마감일·필요 서류가 한 문서에 섞여 있어 무엇부터 할지 모름 `[추정]` |
| 2 | 결혼이민자 | 문서를 사진으로 찍어 번역함 | 파파고·구글 번역 카메라, 범용 AI 챗봇 | 문장은 옮겨지지만 '어느 칸에 어떤 형식으로 쓰는지'는 알 수 없음. 번역이 틀려도 걸러 줄 사람이 없음 `[추정]` |
| 3 | 결혼이민자 → 가족·센터 | 모르는 부분을 물어봄 | 배우자·자녀에게 메신저로 질문, 다누리콜센터(1577-1366)·이민자 종합안내센터(1345) 전화, 가족센터 방문 | 매번 같은 질문을 다시 해야 함. 가족이 대신 해 주면 다음에도 혼자 못 함 `[추정]` / 다누리콜센터는 "1년 365일 24시간", "15개 언어로 상담"이라 운영 시간은 막히는 곳이 아님 `[사실]` 4-kimwonu-bit-01 |
| 4 | 결혼이민자 (또는 가족이 대신) | 실제 신청서를 작성함 | 종이 신청서, 정부24·학교 신청 사이트, 기관 앱 | 연습 없이 바로 실전. 필수 항목 누락·날짜·전화번호 형식 오류를 제출 직전에야 알게 됨 `[가정]` |
| 5 | 결혼이민자 | 본인인증·서류 첨부 후 제출하고 동의 항목에 체크함 | 휴대폰 문자 인증, 간편인증 앱, 공동인증서, 스캔·사진 첨부 | 인증 문자 미수신·세션 만료·첨부 용량 초과에서 막혀 포기하거나 마감을 넘김. 개인정보 제3자 제공·자동 갱신 같은 동의 조항을 이해 못 한 채 체크 `[가정]` |
| 6 | 기관 → 결혼이민자 | 승인·반려·보완 요청 통지를 받고 대응함 | 문자, 우편, 사이트 공지, 학교 앱 | 반려인지 보완 요청인지 구분하지 못해 기회를 놓치거나 불필요하게 다시 신청. 신청 건 진행 상황을 따로 기록하는 곳이 없음 `[추정]` (보완·반려 구분은 C03) |
| 7 | 결혼이민자 | 다음 학기·다음 해에 같은 신청을 다시 함 | 1~6과 같은 도구 | 지난번에 도움을 받은 기록·경험이 남지 않아 같은 과정을 처음부터 반복 `[가정]` |

## 2-3. 데이터와 외부 접점

> 개인정보(이름, 연락처, 주소, 국적·체류 정보, 건강·신체 정보, 아동 정보 등)가 있으면 표시합니다. 3-4에서 LLM에 보내도 되는 정보인지 판단할 때 씁니다.

| 주요 정보 (명사) | 누가 만들고 바꾸나 | 외부에서 오는 정보인가 (어디서?) | 개인정보인가 | 틀리면 생기는 일 |
| --- | --- | --- | --- | --- |
| 원본 서류 (공고문·신청서·계약서 이미지·PDF) | 사용자가 업로드. 서비스는 고치지 않음 | 예. 학교·주민센터·출입국 등 기관이 만든 문서 | 경우에 따라 예. 미리 채워진 이름·주소·학생 정보가 있을 수 있어 LLM에 보내기 전 개인정보 제거 | 판독 실패나 페이지 누락이면 가상 신청서 항목이 빠짐 (R1) |
| 가상 신청서 (연습용 양식: 항목·필수 여부·입력 형식·필요 서류) | LLM이 초안 생성 → 상담원이 수정·승인. 승인 양식은 템플릿으로 재사용 | 아니오 (원본 서류에서 추출) | 아니오. 항목 구조만 담고 값은 담지 않음 | 필수 항목이 빠지거나 형식이 틀리면 잘못된 연습으로 실전 오류 (R2) |
| 신청 마감일·시각, 결과 발표 예정일 | LLM이 추출 → 사용자·상담원이 확인. 기관이 연장 공고하면 갱신 | 예. 공고문, 기관 연장 공지 | 아니오 | 잘못 추출하면 만료 처리가 틀리거나 신청 기회를 놓침 (T1~T5) |
| 신청 건 (현재 상태와 상태 변경 이력) | 사용자·상담원·시스템이 3-2 전이 규칙대로 변경 | 아니오 | 예 (특정 사용자의 신청 내역) | 상태가 틀리면 제출하지 않은 건을 완료로 표시하거나 알림이 빠짐 |
| 사용자 프로필 (이름, 연락처, 사용 언어, 국적, 체류 자격) | 사용자가 입력·수정 | 일부 예. 체류 자격은 외국인등록증·하이코리아 기준 | 예. 국적·체류 정보 포함. 사용 언어 외에는 LLM에 보내지 않음 | 사용 언어가 틀리면 설명을 못 읽음. 체류 정보가 유출되면 피해가 큼 |
| 연습 입력값 | 사용자가 리허설에서 입력. 예시 데이터 모드 가능 | 아니오 | 실제 값으로 연습하면 예 | 연습 값이 실제 기관으로 넘어가면 안 됨 (R3) |
| 실전 화면 내용·실제 입력값 (주민등록번호·외국인등록번호·계좌번호·서명 포함 가능) | 사용자가 공식 사이트·종이에 입력. 서비스는 안내용으로만 화면을 읽고 저장하지 않음 | 예. 정부24·학교 신청 사이트 등 외부 화면 | 예 (고유식별정보 포함). 식별정보는 LLM에 보내지 않고 처리 후 삭제 | 유출 시 법적 문제 (R8, T6, C02) |
| 본인인증 정보 (인증 문자, 일회용 비밀번호, 로그인 정보) | 외부 인증 기관·사이트가 발급, 사용자가 입력 | 예. 통신사·간편인증 앱·공동인증서 | 예. 서비스가 받지도 저장하지도 않음 | 유출되면 스미싱·명의 도용 피해 |
| 동의 항목·주의 조항 확인 기록 | LLM이 주의 조항 요약 → 사용자가 하나씩 직접 체크 | 원문은 예 (계약서·동의서) | 확인 기록 자체는 예 | 요약이 틀리면 위약금·자동 갱신·제3자 제공에 모르고 동의 (R7) |
| 제출 기록 (접수번호·접수증·제출 완료 화면) | 사용자가 공식 경로에서 제출한 뒤 입력 | 예. 기관 접수 시스템 | 예. 접수번호 전체는 LLM에 보내지 않음 | 틀리면 미제출 건을 완료로 보거나 제출한 건을 만료 처리 (R9, R10) |
| 결과 통지 (승인·반려·보완 요청) | 기관이 보냄 → 사용자가 업로드 → LLM이 분류 초안 → 사용자가 확정 | 예. 문자·우편·사이트 공지 | 예. 개인정보 제거 후 LLM에 보냄 | 보완 요청을 반려로 오해하면 불필요한 재신청이나 기회 상실 (R11, C03) |
| 연습·자립 기록 (힌트 요청 수, 오류 수, 위기 상황 통과, 힌트 없는 완주 여부) | 시스템이 자동 기록 | 아니오 | 예 (사용자 행동 기록) | 틀리면 준비가 안 된 사용자에게 리허설 건너뛰기를 제안 (R5, R12) |
| 상담원 검수 기록 (승인·반려·수정 내용) | 상담원이 작성 | 아니오 | 상담원 이름은 예 | 기록이 없으면 잘못 승인된 양식을 추적하지 못하고 자동 승인이 퍼짐 (R2) |

## 2-4. 기존 서비스 벤치마크 (2~3개)

> 기능 목록을 베끼는 것이 아니라, '이 서비스는 어떤 규칙을 어떻게 처리하는가'를 봅니다. 이미 AI·LLM 기능이 있는 서비스라면 그 기능이 무엇을 하는지도 적습니다. 제안서 Ⅱ-5 기존 서비스 분석과 Ⅳ-9 차별점은 이 표에서 나옵니다.
