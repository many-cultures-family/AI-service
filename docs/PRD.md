# PRD (제품 요구사항 문서) v0.1 — 안내판

> **저장 위치:** `docs/PRD.md`

> **내용을 옮겨 적는 문서가 아니라, 어느 문서를 보면 되는지 알려 주는 안내판입니다.** 인수 조건은 `backlog.md`에, 제외 이유는 `mvp-scope.md`에 이미 있습니다. 같은 내용을 두 곳에 쓰면 한쪽만 고쳐졌을 때 어느 쪽이 맞는지 알 수 없습니다. 그래서 **문서 이름과 US 번호로 가리킵니다.**
> 기능은 `backlog.md`에 있는 `F-xx`와 `US`만 씁니다. 새 번호를 만들지 않습니다.
> 구현 순서와 API 라우트 상세는 쓰지 않습니다 (이후 로드맵, `API.md`).
> 모르는 것은 `미정`으로 씁니다. `>`로 시작하는 안내 문장은 지워도 됩니다.

- 버전: v0.1 (초안)
- 작성일: 2026-10-27
- 상태: 검토 전

## 1. 개요
> 가져올 곳: 제안서(v2) 요약. 새로 쓰지 않고 한 줄씩만.

- 프로젝트명: 디딤돌
- 목적 (한 줄): 웹 신청서를 칸 단위로 인식해 칸마다 무엇을 어떤 형식으로 쓰는지 모국어로 알려 주고, 가상 작성 환경에서 직접 작성해 보게 한다 (`backlog.md` US-01·US-02, `mvp-scope.md` 포함 표)
- 사용자 (한 줄): 결혼이민자 (`backlog.md` 스토리 주어)
- 개발 기간: 8주 (`mvp-scope.md` 포함 절 제목)

## 2. 사용자 여정
> 가져올 곳: `docs/requirements/user-flows.md`. 여정은 옮기지 않고 한 줄 요약과 링크만 둡니다.

- 핵심 흐름 (한 줄): 문서 업로드 → OCR 인식 → 입력 항목 선정 → 사전 정보 입력 → 작성 시뮬레이션 → 검증·설명 → 검토·수정 → 중도 포기(취소)
- 자세한 것: [docs/requirements/user-flows.md](requirements/user-flows.md)

## 5. 데이터와 상태
> 가져올 곳: `docs/domain/03-rules-states-llm.md`. 상태값은 그 문서와 똑같이 씁니다. 데이터 구조 확정은 다음 차시입니다.

- 핵심 대상: 작성 건
- 상태값: 수정, 반려, 성공, 취소 (`03-rules-states-llm.md` 3-2)
- 업로드·인식 ~ 검토 단계는 상태가 아니라 '수정' 안의 진행 단계: `03-rules-states-llm.md` 3-2 진행 단계 표
- 자세한 것: [docs/domain/03-rules-states-llm.md](domain/03-rules-states-llm.md)

## 6. LLM의 역할
> 가져올 곳: `03-rules-states-llm.md`. 아래 두 가지를 그대로 가리킵니다.

- LLM이 맡는 일 (한 줄): L1 입력 항목 추론, L2 모국어 쉬운 풀이, L3 서술형 답변 검토 3곳 (`03-rules-states-llm.md` 3-4)
- **사람이 확인하기 전에는 상태가 바뀌지 않는다**: `03-rules-states-llm.md` 3-4 표의 '누가 보고 확인하나'·'이어지는 상태 전이' 열, 3-1 R2·R6·R9
- LLM에 보내지 않을 정보: `03-rules-states-llm.md` 3-4 표의 'LLM에 보내면 안 되는 정보' 열, 3-1 R1·R7·R8
