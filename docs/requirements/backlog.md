## US-01 문서 업로드와 인식

**결혼이민자로서, 웹 신청서 화면을 캡처하거나 PDF로 올려서 문서에 이미 적힌 내 개인정보는 가려진 채 칸 단위로 인식되게 하고 싶다. 왜냐하면 번역 앱에서는 문장만 옮겨질 뿐 칸 단위로 읽히지 않기 때문이다.**

- 우선순위: 필수
- 관련 기능: F-01 (제안서 v2 Ⅳ-11)
- 경로: 정상
- 관련 상태 전이: 업로드됨 → 인식완료
- LLM 관여: 아니오
- 관련 이슈: (다음 주에 채움)

### 인수 조건
- [ ] (정상) PDF·이미지 파일을 올리면 작성 건이 '업로드됨'으로 생긴다.
- [ ] (정상) OCR이 칸을 읽고 문서 속 개인정보를 모두 가리면 '인식완료'로 바뀐다.
- [ ] (실패·거절) 인식에 실패하거나 개인정보가 하나라도 남으면 '업로드됨'에 머물고 다시 올리도록 안내한다.
- [ ] (권한) 작성 건은 올린 본인만 볼 수 있고, 로그인하지 않은 사용자는 올릴 수 없다.

### 미확정
- 허용 파일 형식(PDF·PNG·JPG)과 상한(10MB·10페이지)을 넘는 파일을 거절할지. 제안서에 근거 없음

## US-02 입력 항목 확인과 확정

**결혼이민자로서, 칸마다 무엇을 어떤 형식으로 쓰는지와 필수 여부를 모국어 설명과 함께 원본 화면 옆에 놓고 확인한 뒤 확정하고 싶다. 왜냐하면 지금은 이것을 가족에게 물어봐야 하기 때문이다.**

- 우선순위: 필수
- 관련 기능: F-02 (제안서 v2 Ⅳ-11)
- 경로: 정상
- 관련 상태 전이: 인식완료 → 항목확정
- LLM 관여: 예 (L1 입력 항목 추론)
- 관련 이슈: (다음 주에 채움)

### 인수 조건
- [ ] (정상) '인식완료' 상태인 작성 건을 열면 원본 화면(업로드한 PDF·이미지) 옆에 입력 항목 목록이 나란히 보이고 각 항목에 항목명·입력 형식(예: 010-0000-0000, YYYY.MM.DD)·필수 여부·사용자가 고른 언어의 설명이 모두 표시된다. 항목을 누르면 원본의 해당 칸이 강조된다.
- [ ] (정상) 모든 항목이 규칙 검증(형식·필수 여부가 빠짐없이 있고 형식이 허용 목록에 있음)을 통과한 상태에서 사용자가 '확인했어요'를 누르면 작성 건이 '항목확정'으로 바뀌고 확정된 항목 목록이 저장된다.
- [ ] (실패·거절) 형식이나 필수 여부가 비었거나 허용 목록에 없는 형식이 있는 항목은 해당 항목에 오류가 표시되고 '확인했어요' 버튼이 비활성화되고 상태는 '인식완료'에 머문다.
- [ ] (실패·거절) 사용자가 추론 결과가 원본과 다르다고 표시하고 재분석을 요청하면 상태는 '인식완료'로 유지된 채 재분석이 실행되고 새 결과가 나오면 다시 확인을 거쳐야 한다.
- [ ] (권한) 작성 건을 만든 본인이 아닌 다른 사용자(로그인 사용자 포함)와 비로그인 사용자는 이 작성 건의 원본 화면과 항목 목록을 볼 수 없고 확정·재분석도 요청할 수 없다 (요청 시 접근 거부)
- [ ] (LLM이 있으면) LLM이 추론 결과를 내놓아도 규칙 검증 통과와 사용자의 확인 동작이 모두 있기 전에는 상태가 '인식완료'에서 바뀌지 않는다. LLM 응답만으로는 어떤 경우에도 '항목확정'이 되지 않는다.
- [ ] (LLM이 있으면) LLM에는 OCR 단계에서 개인정보를 가린 텍스트, 칸 위치와 라벨, 사용 언어만 보낸다. 문서에 이미 적힌 이름·주민등록번호·외국인등록번호·연락처 등 개인정보와 사용자의 사전 정보 원본은 LLM 요청에 포함되지 않는다 (제안서 Ⅳ-13)

### 미확정
- 모국어 설명을 몇 개 언어로 제공할지 (제안서 Ⅶ-18 고객사 설정 2번 답변 대기)
- 첫 데모에서 추론할 신청서 양식 범위 (Ⅶ-18 고객사 설정 3번 답변 대기)
- 허용 형식 목록(전화번호·날짜 외)에 무엇을 넣을지

## US-03 추론 결과 재분석 요청

**결혼이민자로서, 추론된 입력 항목이 원본과 다르면 다르다고 표시하고 재분석을 요청하고 싶다. 왜냐하면 틀린 항목 목록으로 작성하면 잘못된 칸에 잘못된 정보를 쓰게 되기 때문이다.**

- 우선순위: 필수
- 관련 기능: F-02 (제안서 v2 Ⅳ-11)
- 경로: 취소·반려
- 관련 상태 전이: 인식완료 → 인식완료 (재분석)
- LLM 관여: 예 (L1 입력 항목 추론)
- 관련 이슈: (다음 주에 채움)

### 인수 조건
- [ ] (정상) 인식완료 상태의 입력 항목 확인 화면에서 사용자가 항목 1개 이상에 '원본과 다름'을 표시하고 재분석을 요청하면, 시스템은 L1을 다시 호출하고 새 입력 항목 목록(항목명, 입력 형식, 필수 여부, 모국어 설명)을 원본 화면 옆에 다시 보여 준다. 작성 건은 인식완료에 머문다
- [ ] (실패·거절) '원본과 다름'으로 표시한 항목이 0개이면 재분석 요청을 받지 않고 L1도 호출하지 않는다. 작성 건 상태와 입력 항목 목록은 바뀌지 않는다
- [ ] (실패·거절) 재분석 결과가 규칙 검증(모든 항목에 입력 형식과 필수 여부가 있는지, 형식이 허용 목록에 있는지)을 통과하지 못하면 작성 건은 인식완료에 머물고 항목확정으로 갈 수 없으며, 어느 항목이 어떤 검증에 실패했는지 사용자 언어로 보여 준다 (03 R2)
- [ ] (권한) 재분석 요청과 입력 항목 목록·원본 화면 조회는 그 작성 건을 만든 사용자 본인만 할 수 있다. 다른 사용자가 요청하면 거절되고 작성 건은 바뀌지 않는다
- [ ] (취소·반려 스토리) 재분석은 사용자만 요청할 수 있고, 인식완료 상태에서 '원본과 다름' 표시가 1개 이상일 때만 인식완료 → 인식완료로 다시 돈다
- [ ] (LLM이 있으면) 재분석 결과가 나와도 사용자가 원본과 비교해 확인하기 전에는 인식완료 → 항목확정으로 바뀌지 않는다
- [ ] (LLM이 있으면) 재분석 때 L1에는 개인정보를 가린 OCR 텍스트, 칸 위치와 라벨, 사용 언어와 함께 사용자가 '원본과 다름'으로 표시한 항목을 보낸다. 문서에 적힌 이름·주민등록번호·외국인등록번호·연락처 등 개인정보와 사전 정보는 보내지 않는다 (제안서 Ⅳ-13 L1)

### 미확정
- 제안서에는 '재분석 요청'만 있고 재분석을 LLM이 다시 하는지는 적혀 있지 않음. LLM 관여 '예'는 L1을 다시 부른다고 보고 적은 것
- '원본과 다름' 표시 때 사용자가 무엇이 다른지 글로 적게 할지, 표시만 받을지
- 재분석 요청 횟수에 상한을 둘지 (LLM 비용, client-meeting-1 피드백 3)
- 03 3-2는 상태를 수정·반려·성공·취소 4개로 바꾸고 인식완료·항목확정을 '수정' 안의 진행 단계로 두었음. 이 스토리의 상태 이름을 어느 쪽에 맞출지

## US-04 사전 정보 입력

**결혼이민자로서, 이름·생년월일·연락처·주소 같은 사전 정보를 항목 뜻을 모국어로 설명받으며 한 번 입력해 두고 다음 문서에도 다시 쓰고 싶다. 왜냐하면 지금은 문서마다 같은 기본 정보를 처음부터 쓰기 때문이다.**

- 우선순위: 필수
- 관련 기능: F-03 (제안서 v2 Ⅳ-11)
- 경로: 정상
- 관련 상태 전이: 항목확정 → 사전정보입력완료
- LLM 관여: 아니오
- 관련 이슈: (다음 주에 채움)

### 인수 조건
- [ ] (정상) 항목확정 상태에서 이 문서의 입력 항목에 연결된 사전 정보 중 아직 등록되지 않은 항목만 입력 칸으로 보여 주고, 칸마다 항목의 뜻을 사용 언어로 함께 보여 준다. 이 과정에서 LLM은 호출하지 않는다
- [ ] (정상) 필요한 사전 정보가 모두 입력되고 규칙 엔진의 형식 검증(예: 연락처 010-0000-0000, 생년월일 YYYY.MM.DD)을 통과하면 그 사용자의 사전 정보로 저장되고, 작성 건은 항목확정 → 사전정보입력완료로 바뀐다
- [ ] (정상) 다음 작성 건에서는 이미 저장된 사전 정보를 다시 묻지 않고 불러온다. 필요한 값이 모두 저장되어 있으면 입력 칸 없이 바로 작성을 시작할 수 있다 (제안서 Ⅳ-12 항목확정 → 작성중)
- [ ] (실패·거절) 형식이 맞지 않는 값은 저장하지 않고, 해당 칸에 오류와 올바른 형식을 사용 언어로 보여 준다. 오류 판정은 규칙 엔진이 하며 작성 건은 항목확정에 머문다 (03 R3)
- [ ] (실패·거절) 이 문서에 필요한 사전 정보가 1개라도 비어 있으면 사전정보입력완료로 바뀌지 않는다
- [ ] (권한) 사전 정보는 입력한 사용자 본인만 보고 고칠 수 있다. 다른 사용자가 조회하거나 고치려 하면 거절된다
- [ ] (개인정보) 저장된 사전 정보 원본은 LLM에 보내지 않는다 (제안서 Ⅳ-13, 03 R8)

### 미확정
- 항목 뜻 설명을 누가 어떤 언어로 미리 만들어 둘지. LLM 관여 '아니오'라서 L1의 모국어 설명을 쓰지 않는다고 보고 적은 것
- 저장된 사전 정보를 고쳤을 때 그 정보를 쓰는 다른 작성 건의 불일치를 다시 검사하는 범위 (03 R11)
- 03 3-2는 상태를 수정·반려·성공·취소 4개로 바꾸고 항목확정·사전정보입력완료를 '수정' 안의 진행 단계로 두었음. 이 스토리의 상태 이름을 어느 쪽에 맞출지

## US-05 서술형 검토와 개인정보 결정

**결혼이민자로서, 서술형 답변의 맞춤법과 질문 의도에 대한 검토 제안을 보고 반영 여부를 직접 고르고, 감지된 개인정보는 그대로 둘지 지울지 직접 정해서 검토를 마치고 싶다. 왜냐하면 혼자 쓴 문장을 누구에게 보여 줘야 할지 모르고, 무엇이 개인정보인지 모른 채 적어 내기 때문이다.**

- 우선순위: 필수
- 관련 기능: F-06, F-07 (제안서 v2 Ⅳ-11)
- 경로: 정상
- 관련 상태 전이: 작성중 → 검토완료
- LLM 관여: 예 (L3 서술형 답변 검토)
- 관련 이슈: (다음 주에 채움)

### 인수 조건
- [ ] (정상) : 고른 검토 제안 반영 여부와 개인정보 유지 여부를 통해 사용자 답변에 제안이 반영 되거나 되지 않는다.
- [ ] (실패·거절) : 서술형 답변을 비워놓으면 검토를 거절한다.
- [ ] (권한) 누가 못 보는지 : 사용자만 볼 수 있다.
- [ ] (LLM이 있으면) : 사람이 확인하기 전에는 상태가 바뀌지 않는다 
- [ ] (LLM이 있으면) LLM에 보내지 않을 정보(제안서 Ⅳ-13) : 개인정보

### 미확정
- 제안서 Ⅳ-12의 작성중 → 검토완료 조건에는 필수 항목 입력과 사전 정보 불일치 0개도 있음(F-04). F-04 스토리를 버렸으므로 이 조건을 어느 스토리에서 다룰지

## US-06 제출 기록

**결혼이민자로서, 공식 사이트에서 직접 제출한 뒤 '제출 완료'를 눌러 작성 건에 제출 사실을 남기고 싶다. 왜냐하면 지금은 신청 건 진행 상황을 따로 기록할 곳이 없기 때문이다.**

- 우선순위: 선택
- 관련 기능: F-08 (제안서 v2 Ⅳ-11)
- 경로: 정상
- 관련 상태 전이: 작성완료 → 제출완료
- LLM 관여: 아니오
- 관련 이슈: (다음 주에 채움)

### 인수 조건

## US-07 작성 건 취소

**결혼이민자로서, 제출 전이라면 어느 단계에서든 작성을 그만두고 그 작성 건을 취소하고 싶다. 왜냐하면 더 이상 신청하지 않을 문서가 내 작성 목록에 남지 않게 하고 싶기 때문이다.**

- 우선순위: 선택
- 관련 기능: F-08 (제안서 v2 Ⅳ-11)
- 경로: 취소·반려
- 관련 상태 전이: 제출 전 모든 상태 → 취소됨
- LLM 관여: 아니오
- 관련 이슈: (다음 주에 채움)

### 인수 조건
- [ ] (정상) : 정상적으로 취소되고 작성 건이 작성 목록에 남지 않는다.
- [ ] (실패·거절) : 유효하지 않은(이미 삭제되었거나 옳지 않은 참조) 작성 건이라면 실패한다.
- [ ] (권한) 누가 못 보는지 : 작성자만 볼 수 있다.
- [ ] (취소·반려 스토리) 누가·어떤 조건에서 바꾸고, 상태가 어디로 가는지 : 이미 쓰고 있던 작성 건이 필요 없어졌을 때 작성 건 취소를 함으로써, 작성 건은 작성 전 어떤 상태에서 취소 상태로 넘어가게 된다.

### 미확정
- 제안서 Ⅳ-11에서 F-08은 '선택'이지만 `user-flows.md` 순서 9(중도 포기 → 취소)에는 들어 있음. 필수로 올릴지
